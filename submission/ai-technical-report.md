## 1. 사용 도구 (요구 4)

| 도구 | 로그 항목 수 | 주된 역할 |
| --- | --- | --- |
| Claude Code (Opus 5) | 22 | 구현, 검증, 판단 |
| Codex | 13 | 초기 요구사항 정리, 문서 정합성, 문제 제기 |
| 두 도구 협업 | 3 | Codex가 제기하고 Claude Code가 판단·구현 |

**여기가 이 제출물의 특징적인 부분이다.** 코딩 에이전트 한 개가 아니라 두 개를 쓰면서
서로의 판단을 교차 검증했다. 실제로 한쪽이 놓친 것을 다른 쪽이 잡은 사례가 여러 건 있다.

오픈소스 의존성: `package.json` 참조 (Phaser 4, Vite 8, TypeScript 7, Vitest 4).
전부 표준 MIT 계열이며 최종 문서에 라이선스를 명시한다.

## 2. 구조 설명 (요구 2)

들어갈 내용. 대부분 확정되어 있어 크게 바뀌지 않는다.

- 엔진과 렌더링 분리. `src/engine/`은 Phaser를 import하지 않는다
- 태그 기반 수정자 파이프라인. 보조능력 15종이 전용 코드 없이 데이터로만 존재
- 원안의 계산 규칙(증가/감소 합산 후 증폭/감폭 곱연산)을 그대로 구현
- 조합 폭발을 태그 시스템으로 제어. 잘못된 조합이 애초에 만들어지지 않음
- 테스트 180개. 원안 문서의 실제 수치를 검증 대상으로 사용

## 3. 사람이 검토·수정·결정한 부분 (요구 6)

**이 항목이 이 문서의 핵심이다.** 후보 사례를 강한 순으로 정리한다.
최종 문서에는 5~7개만 골라 싣는다.

| 사례 | 무슨 일이 있었나 | 로그 날짜 |
| --- | --- | --- |
| **과제 해석 오류** | AI가 `AI 활용`을 게임 내 AI 기능으로 잘못 읽고 스코프를 축소. 사람이 개발 도구를 뜻한다고 정정 | 07-26 |
| **효과 없는 수정 적발** | 렌더 옵션 4개를 추가하고 선명도가 개선됐다고 보고. 빌드·테스트 통과. 사람이 "적절한 수정이냐"고 물어 실측한 결과 전부 기본값이었고 동작이 바뀌지 않았음 | 07-27 |
| **봇이 놓친 버그** | 선택 화면 연타 문제. AI의 헤드리스 검증에서 매번 재현되고 있었으나 도구 문제로 오분류. 사람이 플레이 중 발견 | 07-26 |
| **표기 관습 오용** | 추가 피해를 `+90`으로 표시. 적 위의 `+`는 회복으로 읽힌다는 지적을 받고 규칙 이름 병기로 변경 | 07-29 |
| **검증 불가한 단정** | 트랙패드 동작을 테스트 없이 단정. 사람이 되물어 확인 범위를 다시 따지고 기록을 정정 | 07-29 |
| **다른 AI의 제안 기각** | Codex의 교차 반응 12가지 제안. 진단은 채택하고 처방은 규모 문제로 기각, 측정 가능한 대안으로 대체 | 07-29 |
| **스코프 방향 전환** | 축소가 아니라 확대로. 단 기능 개수가 아니라 엔진 + 데이터 구조로 | 07-26 |
| **팀 구성 오독** | "개발 1명"을 개인 참가로 확대 해석해 제출물을 4종으로 축소 판단. 사람이 2인 팀임을 지적 | 07-26 |
