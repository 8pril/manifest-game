## 1. 예선 과제 목표

NAN 2026 예선 과제의 핵심은 `AI를 활용한 게임 제작`이다. 신청서와 함께 사전 과제 제출물을 제출하며, 서류 및 사전 과제 심사를 거쳐 총 10팀이 본행사에 선발된다.

이번 프로젝트의 목표는 심사자가 링크 클릭만으로 바로 플레이하고, AI 코딩 에이전트를 활용한 개발 과정과 게임 완성도를 빠르게 이해할 수 있는 웹 기반 예선 빌드를 완성하는 것이다.

중요: 이 프로젝트에서 `AI 활용`은 게임 안에 AI 기능을 반드시 넣는다는 뜻이 아니라, 출품작 개발에 사용한 AI 도구, 프롬프트, 활용 내역, 사람이 검토하고 수정한 과정을 제출 문서로 증명한다는 뜻으로 정리한다.

## 3. 참가 및 제출 조건

- 만 19세 이상 누구나 참가 가능
- 개인 또는 팀 참가 가능, 팀은 최대 3인
- 현재 참가 형태는 2인 팀: 기획 1명, 개발 1명
- 팀 참가이므로 팀원 롤 기술서를 제출한다
- 제출물은 참가자 본인의 창작물이어야 함
- 생성형 AI, 오픈소스, 외부 API, 외부 에셋 사용 시 관련 라이선스와 이용 조건을 준수해야 함
- 타인의 저작물, 아이디어, 영상 등을 무단 도용하면 선발 취소 가능
- 접수 마감 후 제출 내용 변경 불가

### 권리 관계 (참가 약관)

제출 전에 팀원 전원이 인지해야 할 조건이다.
공식 페이지의 약관 전문 기준이며, **2026.07.09 시행 개정본**을 반영했다.

- 출품작의 저작권 및 지식재산권은 원칙적으로 참가자에게 귀속된다. (제6조 1항)
- 다만 **수상작에 한해** 주최사가 홍보, 결과 발표, 사례집, 아카이브 목적으로 대회 접수 시작일로부터 **1년간 무상 이용**할 수 있다. (제6조 2항)
- 수상 시 주최사가 수상작 사업화에 대해 **대회 종료일로부터 4개월간 우선협상권**을 갖는다. 채용 여부와 무관하게 적용된다. (제7조)
- 팀 참가 시 팀대표자가 팀 전원을 대표하여 약관에 동의하고 **주최사의 통지를 수령**한다. (제3조 2항)
- **상금은 팀대표자 일괄 지급이 아니라 팀원에게 개별 지급된다.** 각 팀이 배분 내역을 주최사가 정한 방법으로 제출하면 주최사가 그대로 팀원별로 지급한다. 배분 비율 자체는 팀 내부 합의로 정한다. (제5조 4항, **2026.07.09 시행 개정**)
- 배분 내역을 기한까지 제출하지 않거나 팀원이 낸 내역이 서로 어긋나면 **상금 지급이 보류될 수 있고**, 그 지연에 주최사는 책임지지 않는다. (제5조 5항 신설)
- 신분 확인과 지급 관련 정보는 대표자가 아니라 **각 팀원에게** 요청된다. (제5조 7항)
- 소속 회사·단체가 있는 경우, 참가와 출품이 사규·근로계약에 위반되지 않음을 참가자가 보증한다. (제2조 4항)
- 팀원 구성은 원칙적으로 변경 불가. 부득이한 경우 운영진 메일로 문의.

## 5. 제출물별 세부 요구사항

### 5.1 플레이 가능한 빌드 및 소스 코드

- 심사자가 직접 플레이할 수 있는 형태로 제출
- 웹 빌드는 GitHub Pages 등으로 배포하여 링크 클릭만으로 브라우저에서 바로 플레이 가능해야 함
- 모바일 앱은 APK 파일 또는 TestFlight, Google Play 내부 테스트 등 테스트 배포 링크 가능
- 별도 유료 라이선스 없이 실행 가능해야 함
- 보안상 PC 실행 파일, 예를 들어 `.exe`, 직접 제출은 받지 않음
- 전체 소스 코드를 동일 저장소에 포함해야 함
- 커밋 기록을 유지해야 함
- 공개 저장소 제출 권장
- 비공개 저장소일 경우 심사 계정 `dl_gameai_reviewer@nhn.com` 초대 필요

### 5.2 플레이 동영상

- YouTube 링크로 제출
- 30-60초 분량
- 실제 게임 플레이 장면 중심
- AI를 이용한 조작, 합성 또는 타인 영상 도용 불가
- 공개 또는 일부 공개 상태로 업로드

### 5.3 게임 소개 및 설명 문서

PDF에 다음 내용을 포함한다.

- 게임 제목 및 한 줄 소개
- 게임 방법: 목표, 조작, 종료 조건
- 실행 방법: 게임 설치 및 실행 방법
- 플레이 링크 또는 설치 방법
- 플레이 영상 링크

### 5.4 AI 활용 기술 문서

공식 안내는 PDF에 다음 두 항목을 포함하라고 요구한다.

- AI 활용에 대한 기술적 설명(예: 구조 설명, AI 대상 주요 프롬프트 및 지시 사항)
- 외부 에셋 / 오픈소스 출처

제출 문서에서는 첫 항목을 실제 개발 과정에 맞춰 `활용 개요`, `활용 구조`, `주요 프롬프트`,
`도구별 활용`, `사람의 검토·수정·결정`으로 나눠 설명한다. 뒤의 세부 구분은 공식 요구를
충실히 설명하기 위한 내부 구성이지, 별도의 공식 요구사항이 아니다.

### 5.5 팀원 롤 기술서

2인 이상 팀인 경우에만 제출한다.

- 팀원별 이름 및 담당 역할
- 기획, 개발, 아트, AI 활용 등 역할 구분
- 각 팀원이 실제로 맡아 구현한 영역
- 해당 시 협업 및 분업 방식

## 6. 예선 빌드 구현 원칙

이번 예선 빌드는 다음 원칙으로 진행한다.

- 웹에서 즉시 실행 가능한 빌드를 최우선으로 한다.
- 한 판 길이는 실측 후 다시 정한다. 3-5분은 전투 방 5개 시절의 목표였고, 지금은 전투 구역 7개에 보스 4종이다.
- 심사자가 30초 안에 핵심 재미를 이해할 수 있게 한다.
- AI 코딩 에이전트 활용 과정은 프롬프트, 산출물, 검토 기준, 수정 내역으로 명확하게 드러나야 한다.
- 런타임 외부 AI API 의존은 가급적 피한다.
- 사용한 AI 프롬프트, 산출물, 수정 내역은 매 단계 기록한다.
- 외부 에셋과 오픈소스는 사용하는 즉시 출처와 라이선스를 기록한다.

## 7. 권장 기술 방향

현재 프로젝트는 구현 코드가 없는 초기 상태다. 예선 제출 안정성을 위해 다음 구성을 채택한다.

- Vite
- TypeScript
- Phaser 4
- GitHub Pages 배포
- PDF 문서는 Markdown 초안 작성 후 PDF 변환

Unity WebGL도 가능하지만, 빌드 크기와 배포 안정성을 고려하면 예선용으로는 웹 네이티브 스택이 더 빠르고 가볍다. Phaser는 투사체, 지대, 충돌, 스프라이트 풀링을 빠르게 구현하기에 적합하다.

버전은 설치 시점의 최신인 4.2.1을 채택했다. 상세한 판단 근거와 대안은 `docs/game-scope.md` 12절에 있다.

완료 기준:

- 빈 게임 화면이 브라우저에서 표시됨
