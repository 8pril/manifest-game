# NAN 2026 예선 과제 요구사항 및 실행 플랜

작성일: 2026-07-25  
공식 페이지: https://nan2026.nhn.com/

## 1. 예선 과제 목표

NAN 2026 예선 과제의 핵심은 `AI를 활용한 게임 제작`이다. 신청서와 함께 사전 과제 제출물을 제출하며, 서류 및 사전 과제 심사를 거쳐 총 10팀이 본행사에 선발된다.

이번 프로젝트의 목표는 심사자가 링크 클릭만으로 바로 플레이하고, AI 활용 방식과 게임 완성도를 빠르게 이해할 수 있는 웹 기반 예선 빌드를 완성하는 것이다.

## 3. 참가 및 제출 조건

- 만 19세 이상 누구나 참가 가능
- 개인 또는 팀 참가 가능
- 팀은 최대 3인
- 제출물은 참가자 본인의 창작물이어야 함
- 생성형 AI, 오픈소스, 외부 API, 외부 에셋 사용 시 관련 라이선스와 이용 조건을 준수해야 함
- 타인의 저작물, 아이디어, 영상 등을 무단 도용하면 선발 취소 가능
- 접수 마감 후 제출 내용 변경 불가

아래 5개 항목을 모두 제출해야 하며, 하나라도 누락되면 심사 대상에서 제외된다.

| 번호 | 제출물 | 제출 형태 | 비고 |
| --- | --- | --- | --- |

## 5. 제출물별 세부 요구사항

### 5.1 플레이 가능한 빌드 및 소스 코드

- 심사자가 직접 플레이할 수 있는 형태로 제출
- 웹 빌드는 GitHub Pages 등으로 배포하여 링크 클릭만으로 브라우저에서 바로 플레이 가능해야 함
- 모바일 앱은 APK 파일 또는 TestFlight, Google Play 내부 테스트 등 테스트 배포 링크 가능
- 별도 유료 라이선스 없이 실행 가능해야 함
- 보안상 PC 실행 파일, 예를 들어 `.exe`, 직접 제출은 받지 않음
- 전체 소스 코드를 동일 저장소에 포함해야 함
- 커밋 기록을 유지해야 함
- 공개 저장소 제출 권장
- 비공개 저장소일 경우 심사 계정 `dl_gameai_reviewer@nhn.com` 초대 필요

### 5.2 플레이 동영상

- YouTube 링크로 제출
- 30-60초 분량
- 실제 게임 플레이 장면 중심
- AI를 이용한 조작, 합성 또는 타인 영상 도용 불가
- 공개 또는 일부 공개 상태로 업로드

### 5.3 게임 소개 및 설명 문서

PDF에 다음 내용을 포함한다.

- 게임 제목 및 한 줄 소개
- 게임 방법: 목표, 조작, 종료 조건
- 실행 방법: 게임 설치 및 실행 방법
- 플레이 링크 또는 설치 방법
- 플레이 영상 링크

### 5.4 AI 활용 기술 문서

PDF에 다음 내용을 포함한다.

- AI 활용에 대한 기술적 설명
- 구조 설명
- AI 대상 주요 프롬프트 및 지시 사항
- 사용한 AI 도구와 활용 내역
- 외부 에셋 및 오픈소스 출처
- 사람이 검토, 수정, 결정한 부분

### 5.5 팀원 롤 기술서

2인 이상 팀인 경우에만 제출한다.

- 팀원별 이름 및 담당 역할
- 기획, 개발, 아트, AI 활용 등 역할 구분
- 각 팀원이 실제로 맡아 구현한 영역
- 해당 시 협업 및 분업 방식

## 6. 예선 빌드 구현 원칙

이번 예선 빌드는 다음 원칙으로 진행한다.

- 웹에서 즉시 실행 가능한 빌드를 최우선으로 한다.
- 한 판이 3-5분 안에 끝나는 구조를 목표로 한다.
- 심사자가 30초 안에 핵심 재미를 이해할 수 있게 한다.
- AI 활용 지점은 게임 경험 또는 제작 과정에서 명확하게 드러나야 한다.
- 런타임 외부 AI API 의존은 가급적 피한다.
- 사용한 AI 프롬프트, 산출물, 수정 내역은 매 단계 기록한다.
- 외부 에셋과 오픈소스는 사용하는 즉시 출처와 라이선스를 기록한다.

## 7. 권장 기술 방향

현재 프로젝트는 구현 코드가 없는 초기 상태다. 예선 제출 안정성을 위해 다음 구성을 우선 검토한다.

- Vite
- TypeScript
- Phaser 3 또는 Canvas 기반 2D 게임
- GitHub Pages 배포
- PDF 문서는 Markdown 초안 작성 후 PDF 변환

Unity WebGL도 가능하지만, 빌드 크기와 배포 안정성을 고려하면 예선용으로는 웹 네이티브 스택이 더 빠르고 가볍다.

## 8. 실행 플랜

### Phase 0. 기획 압축

목표: 기존 엑셀 초안에서 예선 빌드에 넣을 기능만 결정한다.

액션:

- `01. 기획초안.xlsx`에서 게임 제목, 세계관, 핵심 플레이 루프 추출
- `02. 전투시스템 초안.xlsx`에서 예선 빌드에 들어갈 최소 전투 규칙 추출
- 구현할 기능과 버릴 기능을 분리
- 게임의 목표, 조작, 승리 조건, 패배 조건 확정
- AI 활용 지점 후보를 1-2개로 압축

완료 기준:

- `docs/game-scope.md` 작성
- 한 판의 흐름을 5문장 이내로 설명 가능
- 예선 빌드 기능 목록이 확정됨

### Phase 1. 프로젝트 세팅

목표: 웹에서 실행 가능한 빈 게임 프로젝트를 만든다.

액션:

- Vite + TypeScript 프로젝트 생성
- 게임 엔진 또는 Canvas 구조 결정
- 로컬 개발 서버 실행
- 기본 화면, 시작 버튼, 게임 루프 골격 작성
- Git 저장소 초기화
- GitHub Pages 배포 방식 결정

완료 기준:

- `npm run dev` 실행 가능
- `npm run build` 성공
- 빈 게임 화면이 브라우저에서 표시됨
- 첫 커밋 생성

### Phase 2. 핵심 플레이 구현

목표: 처음부터 끝까지 한 판이 가능한 MVP를 만든다.

액션:

- 플레이어 조작 구현
- 적, 장애물, 카드, 턴, 웨이브 등 핵심 규칙 구현
- 점수, 체력, 자원, 시간 등 핵심 상태 구현
- 승리/패배 조건 구현
- 재시작 플로우 구현
- 최소 UI 구현

완료 기준:

- 설명 없이 한 판 플레이 가능
- 게임 시작, 진행, 종료, 재시작이 모두 동작
- 진행 불가 버그 없음

### Phase 3. AI 활용 요소 적용

목표: AI 활용이 과제 정체성으로 보이도록 구현 또는 제작 과정을 반영한다.

액션:

- AI 활용 방식 최종 선택
- AI로 생성한 기획, 밸런스, 이벤트, 적 패턴, 대사, 레벨 등을 게임에 반영
- 사용 프롬프트와 결과를 `docs/ai-usage-log.md`에 기록
- AI 결과물을 사람이 어떻게 수정했는지 기록
- 런타임 AI 기능이 있다면 실패 대응과 대체 동작 구현

완료 기준:

- 게임 안 또는 문서에서 AI 활용 지점이 명확함
- AI 활용 로그가 최소 5개 이상 기록됨
- 최종 기술 문서에 넣을 사례가 확보됨

### Phase 4. 폴리싱 및 안정화

목표: 심사자가 불편 없이 플레이할 수 있게 완성도를 끌어올린다.

액션:

- UI 가독성 개선
- 튜토리얼 또는 인게임 안내 추가
- 효과음, 배경음, 피드백 추가
- 밸런스 조정
- 데스크톱 및 모바일 브라우저 확인
- 콘솔 에러 제거
- 에셋 경로와 배포 경로 확인

완료 기준:

- GitHub Pages 링크에서 직접 플레이 가능
- Chrome, Safari에서 주요 기능 정상 동작
- 30-60초 영상 촬영에 적합한 장면 확보

### Phase 5. 제출 문서 작성

목표: 제출 PDF 2-3종을 완성한다.

액션:

- 게임 소개 및 설명 문서 작성
- AI 활용 기술 문서 작성
- 팀인 경우 팀원 롤 기술서 작성
- 링크, 실행 방법, 라이선스 정보 검증
- PDF로 변환

완료 기준:

- `submission/game-description.md` 완성
- `submission/ai-technical-report.md` 완성
- 팀인 경우 `submission/team-role-report.md` 완성
- PDF 파일 생성

### Phase 6. 영상 및 최종 제출 리허설

목표: 제출 링크와 파일을 실제 심사자 관점에서 검증한다.

액션:

- 30-60초 실제 플레이 영상 촬영
- YouTube 일부 공개 업로드
- GitHub 저장소 접근 확인
- GitHub Pages 플레이 링크 확인
- PDF 열람 확인
- 신청 폼 제출 전 체크리스트 점검

완료 기준:

- 제출 링크 3종이 외부에서 접근 가능
- 최종 커밋 이후 제출물 변경 없음
- 제출 체크리스트 전체 완료
