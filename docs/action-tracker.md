# NAN 2026 예선 제출 액션 트래커

이 파일은 예선 과제 완성까지의 실행 현황을 추적한다.  
작업을 시작하거나 완료할 때마다 체크박스와 메모를 갱신한다.

## 현재 상태

- 기준일: 2026-07-26
- 참가 형태: **2인 팀 (기획 1명, 개발 1명)** → 팀원 롤 기술서 포함, 제출물 5종
- 현재 프로젝트 상태: 무기 4종 중 2종을 골라 좌/우손으로 운용하고, 방 사이 보조능력 3택1을 고르는 구형 예선 빌드가 완성되어 있다. 2026-07-31 기획 피드백에 따라 이 구조는 최종 목표에서 폐기하고, **검 1종 시작 → 첫 보스 → 마을 → R키 링 메뉴 무기 교체 → 실체화 장비 설정** 구조로 재설계한다.
- 다음 최우선 액션: **보스 다종화 또는 시너지 보조형스킬 추가**. 기준 문서는 `docs/full-concept-implementation-plan.md`

- [x] 무기 4종 기본 공격 구현 (검·활·비전·방패)

- [x] 콤보 발동 스킬 4종 구현 (멸검·연사·비전단검·균열 파동)
- [x] 콤보 게이지 및 발동 전환
- [x] 근접 판정 엔진 (부채꼴)
- [x] 무기 선택 화면 (2종 선택 → 좌/우손 배정)
- [x] 보조능력 15종 데이터 정의

- [ ] 주요 조합 플레이 테스트 및 밸런스 조정 — **기획 담당 몫**

산출물:

- 무기 4종 × 보조능력 15종이 실제 조합되는 빌드
- `game/loadout.ts` 로드아웃 모델 + 테스트

메모: 슬롯을 원안대로 스킬당 2개로 되돌리면서, 보조능력이 어느 스킬에

슬롯이 8개가 되어 3회 선택을 원안 규칙 그대로 소화한다.
12개 무기 조합 전부에서 3회 선택이 가능한지 테스트로 검증했다.

### 팀원 롤 기술서 요구사항

공식 요구사항은 다음 4개 항목이다.

- 팀원별 이름 / 담당 역할 (기획·개발·아트·AI 활용 등)
- 각 팀원이 실제로 맡아 구현한 영역
- (해당 시) 협업·분업 방식

`실제로 맡아 구현한 영역`을 요구하므로, 기획 담당의 기여도 산출물로 추적 가능해야 한다. `docs/game-scope.md`, 밸런스 수치 결정, 조합 플레이 테스트 기록, 게임 소개 문서가 그 근거가 된다. 커밋 기록도 심사 대상이므로, 기획 담당이 작성·수정한 문서는 해당 인물 명의로 커밋되는 것이 바람직하다.

보스 드랍/획득, 최소 패턴, 보스 다종화, 보조형스킬 1형/2형 분류, 시너지 데이터, 마을 장착 UI, localStorage 저장은 들어갔다.
이제 마을 UI에서 후보 설명/수치 미리보기를 보여주거나, 효과음을 붙여 체감 완성도를 올려야 한다.

현재 상태:

- 검 1종 시작, 첫 보스 후 활/방패 해금, 마을 진입, R키 링 메뉴는 구현됨
- 예선 방 구성은 `흐린 입구 → 첫 문지기(문지기) → 마을 → 해금 시험장 → 파편 회랑 → 무너진 문(무너진 문)`으로 정렬됨. 한 판에 서로 다른 보스 두 종류를 만난다
- 무기별 콤보스킬 1칸 + 보조형 2칸은 모델과 전투 해석에 연결됨
- `canAttach` 기반 태그/슬롯 검증은 장착 읽기 경로에 연결됨
- 대체 발동용 공격 간격 정책은 고정됨. 지대형은 `comboInterval`, 투사체형은 기본 `cooldown`을 쓴다
- `PlayerProgress`에 id 배열 기반 `ownedComboSkills`와 `ownedSupports`가 추가됨
- 미보유 콤보스킬/보조형스킬은 `configureManifestation`과 전투 해석 경로에서 적용되지 않음
- 첫 보스와 최종 보스의 확정 드랍이 `reward` 데이터로 정의되고, 클리어 시 보유 목록에 반영됨
- 첫 보스 문지기는 돌진 예고/돌진, 돌진 벽충돌 멈춤, 체력 70%/35% 사냥개 소환 패턴을 가짐
- 최종 보스 무너진 문은 충격파 예고/충격파, 체력 75%/45% 파편 탄막 패턴을 가짐
- 보스 처치 순간 현재 방 보상 기반 드랍 연출이 표시됨
- 보조형스킬은 `slotType`으로 1형/2형이 구분됨
- 2형 시너지 보조형스킬 3종이 추가됨: 상처 추적, 상처 공명, 균열 공명
- 2형 보조의 `statusDamage` 거동은 이미 걸린 상태이상을 보고 피해를 증폭함
- 첫 마을 진입 시 보유한 콤보스킬/보조형스킬을 직접 장착하는 마을 UI가 표시됨
- 마을 UI에서 R링 무기 후보 4칸을 직접 변경할 수 있음
- `configureDefaultTownLoadout` 자동 장착 경로는 제거됨
- 보유 무기/콤보스킬/보조형스킬/configs/R링 후보는 `localStorage`에 저장되고 다음 판 시작 시 복원됨
- 구형 웨이브 사이 3택1 장착 경로와 시작 무기 2종 선택 화면은 제거됨
- 콤보스킬은 각성 중 기본 공격을 대체하며, 콤보 지속시간은 5초
- 각성 중 콤보스킬 명중도 무기별 상태이상과 상태 반응을 유지함
- 단일 대상 각성 배율은 `src/game/dps.bench.test.ts` 기준 1.5-2.5배 안에 들어옴

개발자가 먼저 할 것:

1. 마을 UI의 장착 후보 설명/미리보기를 보강한다.
2. 실제 효과음 4개를 추가한다.
3. 최종 보스 충격파/파편 탄막을 플레이 테스트로 난이도 조정한다.

금지/주의:

- 콤보스킬별 whitelist는 만들지 않는다. 이미 `canAttach`가 태그와 슬롯 수를 검증한다.
- `primarySupportId` / `synergySupportId`는 `slotType`으로 구분된다. 마을 UI도 같은 규칙을 써야 한다.
- `ownedSupports`와 `ownedComboSkills`는 객체 참조가 아니라 id 문자열 배열로 둔다. 그래야 localStorage 저장 때 마이그레이션 없이 JSON 직렬화할 수 있다.
- 무리 상대 각성 배율은 지대형이 더 높아도 된다. 범위 장악이 지대형의 정체성이므로 단일 대상 기준과 같은 상한을 강제하지 않는다.
- 투사체형은 기본적으로 총 피해가 여러 적에게 나뉜다. 다중 대상 이득은 관통/연쇄/갈래 같은 보조형스킬로 만든다.

인계 문서: `docs/playtest-brief.md`, `docs/concept-brief.md`, `docs/art-spec.md`

순서: 세계관·이름(`concept-brief.md`) → 아트 프롬프트 확정 → 아트 생성.
플레이 테스트는 이와 무관하게 병행 가능하다.

기획 담당이 확인할 것:

1. 한 판이 3-5분 안에 끝나는지. 너무 길거나 짧으면 웨이브 구성을 조정한다.
2. 12개 무기 조합의 난이도 차이. 특정 조합이 압도적으로 쉽거나 어려운지.
3. 몰이꾼가 카이팅을 실제로 벌하는지. 너무 아프거나 무의미하지 않은지.
4. 상태이상 4종이 플레이 중 눈에 보이는지. 점 표시만으로 충분한지.
5. 콤보 발동(5타)이 적절한 빈도로 터지는지.
6. 보스 클리어가 가능한지. **승리 화면은 아직 실제 플레이로 도달하지 못했다.**

밸런스 수치는 다음 파일에 모여 있어 코드를 몰라도 조정할 수 있다:

- `src/game/enemy.ts`   적 체력·속도·피해·사거리
- `src/game/waves.ts`   웨이브별 적 구성
- `src/data/weapons.ts` 무기 피해·사거리·쿨다운
- `src/game/combo.ts`   콤보 요구치와 지속시간
- `src/game/run.ts`     플레이어 체력과 무적 시간

개발자가 이어서 할 것 (피드백 수령 후):

7. 튜토리얼, UI 가독성, 피격/상태/발동 스킬 피드백 폴리싱
