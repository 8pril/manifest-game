# 플레이 테스트 요청

작성일: 2026-07-26
최종 수정: 2026-08-01
대상: 기획 담당

플레이 링크: **https://8pril.github.io/nan2026-game/**

설치 없이 브라우저에서 바로 실행된다. Chrome 권장.
배포 링크는 최신 빌드다. 별도로 로컬을 띄울 필요는 없다.

## 한 판 구조

**검 1종으로 시작한다.** 오른손은 비어 있고, 콤보스킬(멸검)도 아직 없다.
즉 처음에는 **검 기본 공격만** 나간다. 첫 보스를 잡아야 무기와 콤보스킬이 열린다.

```
검 1종 시작 → 흐린 입구 → 첫 문지기(보스)
            → 바닥 드랍에 가까이 가서 자동 획득 → 마을(NPC와 F 대화)
            → 해금 시험장 → 파편 회랑 → 무너진 문(보스) → 승리 / 패배
```

**보스를 두 번 만난다.** 첫 문지기는 활·방패와 콤보스킬을 열어주고, 무너진 문이 마무리다.
무너진 문은 비전을 준다. 비전은 그 판에서는 못 쓰고 다음 판부터 쓴다.

**보상은 바닥에 떨어진다.** 보스를 잡으면 금색 마름모가 바닥에 남는다.
가까이 가면 **자동으로 획득된다.** 조금 떨어져 있을 때 `가까이 가면 획득` 안내가 작게 뜬다.
**줍기 전에는 출구가 열리지 않는다.**

**마을은 걸어다니는 방이다.** 들어가도 아무 창이 뜨지 않는다.
NPC(파란 기둥)에게 다가가 `F 대화`로 장비 설정 패널을 연다. 다음 전투는 오른쪽 출구로 걸어 나가면 시작된다.

**방은 화면보다 크다.** 카메라가 따라가고, 화면 밖의 적과 출구는 가장자리 화살표로 표시된다.

| 입력 | 동작 |
| --- | --- |
| WASD | 이동 |
| 마우스 | 조준 |
| 좌클릭 | 왼손 무기 |
| 우클릭 **또는 Shift** | 오른손 무기 |
| Space | 대시 (대시 중 무적, 적을 통과함) |
| F | 마을 NPC 대화 |
| R (누르고 있기) | 무기 교체 링 메뉴 — 첫 보스 이후 해금 |
| R (마을 패널이 열려 있을 때) | 패널 닫기 |
| R (판이 끝난 뒤) | 다시 시작 |
| P | 일시정지 메뉴 |
| Shift+R (일시정지·결과 화면에서) | **저장 기록 지우고 처음부터** |

### 콤보

기본 공격이 **5번 명중하면** 그 무기가 각성 상태가 되고, **콤보가 끊길 때까지 유지된다.**
각성 중에는 기본 공격 대신 콤보스킬 형태로 공격한다.
마지막 명중 후 5초 동안 다시 맞히지 못하면 기본 공격으로 돌아온다.
콤보스킬이 명중하면 지속시간이 갱신되므로, 계속 맞히면 각성이 이어진다.

화면 아래 중앙에 좌/우손 콤보 배지가 있다. 게이지가 5칸 차면 `MAX`가 된다.
**콤보스킬을 아직 못 얻은 무기는 `잠김`으로 뜨고, 게이지가 차도 기본 공격만 나간다.**

### 저장

진행은 브라우저에 저장된다. 해금한 무기·콤보스킬·보조형스킬과 마을 세팅이 다음 판에 남는다.
단 **손에 든 무기는 매 판 검 1종으로 돌아가고, 1번 방에서는 R링이 열리지 않는다.**
도입부를 매 판 똑같이 보이게 하려는 의도다.

처음부터 다시 보고 싶으면 **P → Shift+R**.

## 확인할 것

무기 조합은 12가지지만 전부 할 필요는 없다. **3~4가지만** 골라도 충분하다.

1. **한 판 소요 시간.** 목표는 3~5분.
2. **첫 보스까지의 손맛.** 검 기본 공격만으로 방 1개와 보스 하나를 넘는 구간이다.
   지루한지, 아니면 첫 보상이 그만큼 크게 느껴지는지.
3. **첫 문지기 난이도.** 배치는 보스 1 + 사냥개 4지만, 보스가 체력 70%/35%에서 사냥개를 소환한다.
   자동 검증 봇 기준으로 **한때 생존 적이 10마리까지 늘었고, 봇은 이 방을 대부분 통과하지 못했다.**
   기획 의도가 "1~2번 방은 학습 구간"이었는데 소환이 그걸 되돌리고 있는지 확인이 필요하다.
4. **방패의 보스전 역할.** 방패는 피해가 가장 낮은 대신 두 가지를 갖는다.
   **방패로 공격할 때만 0.24초짜리 보호 시간이 열린다.** 손에 들고만 있으면 켜지지 않는다.
   그 시간 안에 맞으면 에너지 보호막 45가 체력보다 먼저 닳고, 받는 피해도 45%로 준다.
   보호막은 재생되지 않고 방을 클리어해야 회복된다.

   HUD의 보호막 바는 방패를 손에 들고 있으면 계속 보이고, 보호 시간에만 밝아진다.

   보호 시간 비율은 이렇게 된다.

   | 상황 | 보호 시간 |
   | --- | --- |
   | 방패로 계속 공격 | 0.24초 / 0.42초 = **57%** |
   | 각성 중 (균열 파동) | 0.24초 / 1.2초 = **20%** |
   | 공격을 멈추고 물러남 | **0%** |

   여기에 **보스는 넉백·기절에 걸리지 않는다.**

   > **방패로 보스를 상대할 때, 막으면서 버틴다는 느낌이 드는가.**
   > **특히 각성 5초 동안 더 강해진 느낌인가, 더 위험해진 느낌인가.**

   보호막이 "방을 버티는 자원"이 아니라 "가끔 한 대 막아주는 것"으로 느껴진다면
   보호 시간을 늘리거나 각성 중 발동 간격에 맞춰 늘리는 쪽을 검토한다.
5. **투사체 무기의 보스전 속도.** 여러 발이 큰 대상에게 전부 꽂히는 문제 때문에
   발당 피해에 전역 보정을 넣었다(총합 배율 = 투사체 수^0.6).
   그만큼 콤보스킬 피해를 올렸지만(연사 36→51, 비전단검 32→54), 실제로 답답한지 확인이 필요하다.
6. **몰이꾼(노란 삼각형, 해금 시험장부터)이 카이팅을 막는지.** 너무 아픈지, 무시해도 되는지.
7. **상태이상이 눈에 보이는지.** 적 머리 위 색 점에 더해 발동 순간에 연출을 넣었다.
   상처 폭발(붉은 링), 낙인 소모(보라 파동 + 플레이어 오라), 기절(흰 링 + 플래시), 벽 충돌(충격 + 흔들림).
   - **확인 필요:** 상처 폭발은 5스택이 필요한데 베기 46 피해 기준 사냥개(체력 52)와 몰이꾼(60)은
     2타에 죽어 도달하지 못한다. 껍데기(260)와 보스에서만 터진다.
     이대로 "단단한 적을 무너뜨리는 마무리"로 둘지 판단이 필요하다.
8. **콤보 발동 빈도.** 5타가 너무 빠른지 느린지.
   - 콤보는 **적 하나 맞힐 때마다** 1씩 오른다. 근접 무기로 3마리를 한 번에 쓸면 콤보가 3 오른다.
     적이 몰린 상황에서 훨씬 자주 터진다. 의도한 맛인지 판단이 필요하다.
9. **검이 필수 픽처럼 느껴지는지.** 상처가 쌓인 적을 다른 무기로 때리면 스택당 추가 피해가 들어간다.
   상태이상 4종 중 상처에만 이 반응이 있어 **검을 안 고르면 손해**라고 느껴지는지.
10. **마지막 전투 클리어 가능 여부.** **아직 사람이 승리 화면에 도달한 적이 없다.**
    자동 검증 봇은 첫 보스까지만 잡아봤다. 도달하면 알려줄 것.
11. **진행이 막히는 곳.** 특히 바닥 드랍을 못 줍는 상황이 생기면 바로 알릴 것.
    줍기 전에는 출구가 안 열리므로, 드랍이 닿지 않는 곳에 떨어지면 판이 막힌다.

## 기록 형식

```
[플레이 1]
무기: 검 + 활
결과: 파편 회랑에서 패배 / 소요 4분 20초
난이도: 첫 문지기까지는 쉬웠는데 해금 시험장 몰이꾼부터 급격히 어려움
느낀 점:
```

몇 판이든 이 형식으로 누적하면 된다. 이 기록은 팀원 롤 기술서의 근거 자료로 들어간다.

## 수치 직접 조정

밸런스 수치는 5개 파일에 모여 있다. 코드를 몰라도 숫자만 바꾸면 된다.

| 파일 | 조정 대상 |
| --- | --- |
| `src/game/enemy.ts` | 적 체력·속도·피해·사거리, 보스 패턴 임계값 |
| `src/game/rooms.ts` | 방별 적 구성, 방 크기, 방 보상 |
| `src/data/weapons.ts` | 무기 피해·사거리·쿨다운·콤보 간격 |
| `src/game/combo.ts` | 콤보 요구치(현재 5)·지속시간(현재 5초) |
| `src/game/run.ts` | 플레이어 체력·무적 시간·방패 보호막 |

**바꾼 내용은 직접 커밋한다.** 커밋 기록도 심사 대상이므로 기획 담당 명의로 남는 편이 기술서 작성에 유리하다.

수치를 바꾼 뒤에는 `npm test`를 돌린다. `src/game/dps.bench.test.ts`가 무기별 각성 배율을
계산해 1.5~2.5배 범위를 벗어나면 실패시킨다. 한 무기만 세지거나 약해지는 것을 막는 장치다.

### 개발용 진입 파라미터

로컬 실행 시 주소 뒤에 붙여 특정 방·무기로 바로 시작할 수 있다. **방 번호는 1부터다.**

```bash
npm install
npm run dev
# http://localhost:5173/?wave=2                     첫 문지기 방부터
# http://localhost:5173/?left=bow&right=arcane       무기를 지정해서 시작
# http://localhost:5173/?wave=4&left=shield          둘 다 지정
```

`left`나 `right`를 지정하면 저장된 진행을 무시하고 그 무기로 시작한다.
대신 저장된 R링 후보도 같이 버려지므로, 링 교체를 볼 때는 파라미터 없이 들어가는 쪽이 맞다.

## 아트 작업

**바로 생성을 시작하면 된다.** 2026-07-30에 기획 담당이 `docs/concept-brief.md`를 채웠고,
`docs/art-spec.md`의 프롬프트는 그 내용으로 다시 썼다. 개발 쪽에서 임시로 지어냈던
단어는 전부 버렸다.

- 세계관·주인공·장소·톤: 확정
- 적 이름(사냥개·껍데기·몰이꾼·문지기): 확정
- 제목 `MANIFEST`: 개발 제안 상태이며 **기획 확인만 남았다.** 아트 생성을 막지 않는다

생성한 이미지는 `assets-raw/` 폴더에 파일명 그대로 넣고 커밋하면 개발 쪽에서 반영한다.
필요한 이미지 목록과 프롬프트는 `docs/art-spec.md`에 있다.

플레이 테스트와 병행 가능하다. 순서를 정하자면 플레이를 먼저 해보는 쪽이 낫다.
게임이 어떻게 움직이는지 봐야 어떤 그림이 필요한지 감이 잡힌다.

## 알아둘 것

- 승리 화면은 아직 사람의 실제 플레이로 확인된 적이 없다
- 효과음은 들어갔다(공격·피격·처치·콤보·보스 예고·보상). 음소거 기능은 아직 없다
- 튜토리얼 텍스트는 없다. 조작 안내는 화면 우상단 한 줄뿐이다
- 진행이 막히는 버그를 만나면 화면과 직전 행동을 함께 알릴 것
